# 01 - Análise dos Requisitos

## Objetivo

Realizar a identificação e análise dos requisitos da aplicação disponibilizada para o desafio técnico da Sea Tecnologia, utilizando como base o enunciado do desafio e o protótipo fornecido.

## Fontes de Informação

A análise foi realizada com base nas seguintes fontes:

* Enunciado do desafio técnico;
* Protótipo disponibilizado pela Sea Tecnologia;
* Aplicação web disponibilizada para testes.

---

## Requisitos de Design

### RD-001 – Conformidade com o Protótipo

A aplicação deve refletir o design e a estrutura definidos no protótipo.

### RD-002 – Fonte

A fonte utilizada na aplicação deve corresponder à especificada no protótipo.

### RD-003 – Cores

As cores utilizadas na aplicação devem corresponder às definidas no protótipo.

### RD-004 – Componentes

Todos os componentes previstos no protótipo devem estar presentes na aplicação.

---

## Requisitos Funcionais

### RF-001 – Cadastro de Funcionário

O sistema deve permitir cadastrar um funcionário.

### RF-002 – Edição de Funcionário

O sistema deve permitir editar um funcionário previamente cadastrado.

### RF-003 – Exclusão de Funcionário

O sistema deve permitir excluir um funcionário previamente cadastrado.

### RF-004 – Listagem de Funcionários

O sistema deve exibir os funcionários cadastrados.

### RF-005 – Filtro de Funcionários Ativos

O sistema deve permitir visualizar apenas funcionários ativos.

### RF-006 – Limpeza de Filtros

O sistema deve permitir remover filtros aplicados.

### RF-007 – Status do Funcionário

O sistema deve permitir definir o funcionário como Ativo ou Inativo.

### RF-008 – Dados do Funcionário

O sistema deve permitir informar:

* Nome;
* CPF;
* RG;
* Sexo;
* Data de Nascimento;
* Cargo.

### RF-009 – Gestão de EPIs

O sistema deve permitir:

* Selecionar atividade;
* Selecionar EPI;
* Informar número do CA;
* Adicionar EPI;
* Adicionar múltiplas atividades;
* Informar que o trabalhador não utiliza EPI.

### RF-010 – Upload de Documento

O sistema deve permitir anexar atestado de saúde.

### RF-011 – Salvamento de Dados

O sistema deve permitir salvar os dados do funcionário.

### RF-012 – Persistência de Dados

As informações cadastradas devem ser armazenadas corretamente pelo sistema.

### RF-013 – Recuperação de Dados

As informações cadastradas devem ser recuperadas corretamente sem perda ou inconsistência.

### RF-014 – Validação de CPF

O sistema deve validar corretamente o CPF informado.

### RF-015 – Validação de Data

O sistema deve validar corretamente a data informada.

### RF-016 – Navegação

Os links e menus devem direcionar para os componentes corretos.

### RF-017 – Página "Em Breve"

Os itens ainda não implementados devem direcionar para o componente "Em breve".

---

## Requisitos Não Funcionais

### RNF-001 – Compatibilidade entre Navegadores

A aplicação deve funcionar corretamente nos principais navegadores web.

### RNF-002 – Consistência Visual

A aplicação deve manter comportamento visual consistente durante operações de cadastro, edição, consulta e exclusão.

---

## Considerações Finais

A análise dos requisitos permitiu identificar os principais comportamentos esperados da aplicação e os critérios de qualidade definidos pela Sea Tecnologia. Os requisitos levantados servirão como base para a elaboração do Plano de Testes, criação dos Casos de Teste, execução dos testes manuais e desenvolvimento dos testes automatizados.
